# 115 获取Cookie

用 115 App 扫码登录，直接拿到 115 的 Cookie 串，可选要绑定的客户端（web / android / ios / …）。

## 功能

- **扫码取 Cookie**：网页端接口生成二维码，115 App 扫一扫确认后自动换取 Cookie。
- **可选登录设备**：web / android / ios / linux / mac / windows / tv / 支付宝小程序 / 微信小程序 / qandroid 共 10 种客户端。
- **自动保存 + 复制**：结果写入本地存储并复制到剪贴板，下次打开直接显示上次的 Cookie。
- **失败原因可见**：直接展示 115 返回的错误原因；若 web 端被限制会自动改试 qandroid。
- **检测 Cookie**：随时点一下就能验证已保存的 Cookie 是否还有效，失效时直接显示 115 返回的原因。

## 首次使用

1. 运行脚本，在「登录设备」里选择要绑定的客户端（给网页版 115 工具用就保持默认的 web）。
2. 用 115 App 扫描屏幕上的二维码，并在手机上确认登录。
3. Cookie 会自动保存并复制到剪贴板，点「复制 Cookie」可再复制一次。
4. 过一段时间可以回来点「检测 Cookie」验证是否还有效（会向 115 真实请求一次）。

## 注意事项

- **要填给网页版 115 工具（AList、115 云下载等）的必须是 web Cookie**：`UID` 里带 `_F1_` 才认，App 登录产生的 `_A1_` 会被判「登录超时」。
- 同一个客户端已登录的设备会被踢下线：选 ios 扫码会踢掉手机上其它 ios 登录态。
- **115 App 扫码时显示的客户端名是固定的，不会跟着选择变**：这是 115 自己的提示行为（上游作者原话：「第一步获取一个 token，我用的网页端的接口，这不影响最终绑定的客户端，只是会看上去误解」），不是脚本问题。
- 真正决定「绑定哪个客户端、踢掉哪个设备的登录」的是换取 Cookie 的请求（`POST /app/1.0/{设备}/1.0/login/qrcode/`），这一条一直是按你选的设备走的。
- 二维码有效期约几分钟，过期后点「重获Cookie」。
- **「检测 Cookie」走的是网页接口**：命中 `state=true` 就是有效；失效会返回 `errno 990001 登录超时`。所以 App 版 Cookie（`_A1_`）在这里天然会被判失效（不是真的过期，而是网页接口不认它），脚本会额外给出提示。
- 检测结果不写入本地存储，每次打开需要手动点一次，避免看到已经过期的「有效」。

### 1.4.0（2026-10-12）

- **纠正 1.3.0 的错误结论并回退**：1.3.0 以为「二维码要按所选设备生成」，实测 + 上游作者确认后表明这是错的 —— 115 的 token 接口固定用网页端，**扫码时 App 上显示的客户端名是 115 固定的提示，本来就不会跟着选择变**。
- 真正决定绑定哪个客户端的是换取 Cookie 的请求，这一步从 1.1.0 起一直是按所选设备走的。
- 界面加了解释文字，避免再被二维码里的客户端提示误导。

### 1.3.0（2026-10-12）⚠️ 已被 1.4.0 回退

- **修复：选择登录设备不生效。** 之前只有「换取 Cookie」的请求带着所选设备，二维码却始终由同一个接口（ `/api/1.0/web/1.0/token/`）生成，所以不管选什么都扫出同一个设备。现在二维码也按所选设备生成。
- 解码验证了二维码内容：payload 里只有 `dg-<uid>`，本身不带设备信息 —— 设备是由 **token 端点** 决定的，这是唯一一个在扫码前就已确定的设备相关参数。
- linux / mac / windows / tv 的 token 接口不返回扫码链接，改为用 115 自己渲染的二维码图（`/api/1.0/{设备}/1.0/qrcode?uid=`）。
- 二维码图片小于 260px 时不再放大（放大反而不好扫）。

### 1.2.0（2026-10-12）

- 新增「检测 Cookie」按钮（在「复制 Cookie」上方）：调用 `webapi.115.com/files` 校验当前 Cookie，`state=true` 显示有效与根目录条目数，失效时直接展示 115 返回的原因（实测 `errno 990001「登录超时，请重新登录。」`）。
- 检测结果不写盘（换 Cookie、重新扫码、清除后自动重置），避免看到过期的「有效」。
- 识别 `UID` 中的 `_F1_`（web 版）/ `_A1_`（App 版），App 版 Cookie 被网页接口判失效时会给出额外提示。
- 检测成功 / 失败分别带一次触感反馈。
